## 核心原则

用最少 Tokens 传递最多有效信息，避免因自动压缩导致的任务中断。

## 会话管理策略

### 会话拆分时机

遇到以下情况时应**立即拆分**会话：

- 完成一个独立功能模块
- 解决一个复杂 bug 后
- 做出重要架构决策后
- 每天工作结束时
- 上下文使用超过 70% 时

示例：

```bash
# 不要在一个会话中完成整个项目
[会话1] 需求分析 + 技术选型 → 生成快照
[会话2] 项目初始化 + 核心框架 → 生成快照
[会话3] 具体功能实现 → 生成快照
```

## 信息过滤规则

### 必须传递的信息

```
✓ 已确定的接口定义
✓ 当前代码的文件结构
✓ 正在使用的依赖库版本
✓ 下一步要修改的具体文件
✓ 已确认的业务规则
```

### 必须丢弃的信息

```
✗ 调试过程中的 console.log
✗ 被否决的技术方案详情
✗ 代码的完整历史修改记录
✗ 与下一步无关的 API 文档
✗ 已解决的错误堆栈详情
```

## 实际操作流程

### 场景：开发用户登录模块

**会话 A 结束时生成快照**：

```markdown
## 用户登录模块 - 快照v1
**时间**：2026-05-12 14:30

### 🎯 当前目标
实现用户登录功能（前端+后端）

### ✅ 已完成
- 前端：创建`/src/pages/login`目录，基础UI完成
- 后端：`/api/auth/login`接口框架搭建
- 数据库：用户表结构设计完成

### ⏭️ 下一步
1. 实现前端表单验证（邮箱+密码）
2. 完成后端JWT生成逻辑
3. 连接数据库验证用户

### 🔑 关键信息
- 前端：React + Ant Design，表单组件路径`/src/components/LoginForm.tsx`
- 后端：Express + JWT，接口路径`/routes/auth.js`
- 数据库：MySQL，表结构见`schema/users.sql`
- 已安装依赖：`jsonwebtoken`, `bcryptjs`, `express-validator`

### ⚠️ 注意事项
- 密码需bcrypt加密存储
- JWT有效期设为7天
- 需处理重复注册验证
```

**开启会话 B 时**：

```
# 粘贴上面的快照，然后直接给出任务
基于以上快照，请继续实现任务：
1. 首先完成LoginForm.tsx的表单验证逻辑
2. 然后实现JWT生成中间件
当前遇到的具体问题是：验证规则已定义但未与UI绑定
```

## 紧急情况处理

### 上下文即将满时

```bash
# 立即执行
1. 停止新任务，保存当前状态
2. 运行：extract_current_state()  # 提取核心状态
3. 生成紧急快照（只保留绝对必要信息）
4. 复制快照，开启新会话
```

### 紧急快照模板

```markdown
## 紧急快照
**文件**：{当前编辑的文件}
**函数**：{正在修改的函数}
**行号**：{当前行}
**状态**：{完成/未完成}
**下一步**：{接下来要做的具体一行操作}
**关键变量**：{当前作用域的关键变量}
```

## 质量检查清单

在切换会话前，检查：

- [ ] 快照是否超过 200 字？
- [ ] 是否包含具体的文件路径？
- [ ] 是否明确下一步的 1-3 个具体任务？
- [ ] 是否包含必要的代码片段（不超过 20 行）？
- [ ] 是否已清理调试信息、控制台输出？
- [ ] 外部文档是否已更新？

## 性能数据

| 策略 | Token 消耗 | 信息保留率 | 推荐场景 |
|------|-----------|------------|----------|
| 完整复制历史 | 1000-5000+ | 100% | 法律文档、精确恢复 |
| 结构化快照 | 150-300 | 90-95% | 日常开发（推荐） |
| 仅关键信息 | 50-100 | 70-80% | 简单任务延续 |
| 全新开始 | 0 | 0% | 完全独立新任务 |

## 总结

**核心工作流**：

```
编码 → 达到检查点 → 生成结构化快照 →
开启新会话 → 粘贴快照 → 继续编码
```

**关键数字**：

- 快照长度：100-300 字为佳
- 代码片段：不超过 20 行
- 任务项：每次 1-3 个具体任务
- 检查频率：每 1-2 小时或完成小功能后

**记住**：快照不是文档，是**接力棒**——只需让下一个 AI 知道该从哪里继续跑。
